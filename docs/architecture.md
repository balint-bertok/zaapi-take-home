# Architecture

Answers: how does the system work, what must always hold, and what has already been rejected?

## Flow

A static single-page app (ADR 0001). No backend, no network: every click changes in-browser state only.

- **Routes.** Each feature folder (`src/features/auth`, `tickets`, `ai`, `automations`, `settings`) exports its own `routes.tsx`, a list of `AppRoute` (`path`, `title`, `layout`, lazily loaded `Page`). `src/routes.tsx` only concatenates them; it is the one route table, and the invariant suites walk it. `src/App.tsx` mounts `auth` routes bare and `app` routes under `AppLayout`, sets `document.title` from the route (titles from the catalog's `seo.metaTitle`, in `src/lib/route.ts`), and sends `/` and any unknown URL to `/login`.
- **Shell.** `AppLayout` (`src/shell/`) draws the free-trial banner above every `app` page. A dashboard page wraps itself in `<ShellPage section breadcrumb>`, which adds the icon rail, the section sidebar (`src/shell/sections.ts`, labels from the English catalog) and the content card; with a breadcrumb it also adds the header and the standard page container. Flow Builder's canvas is the one `app` page without rail or sidebar. Anything that looks clickable but leads to an uncaptured page renders through `<Inert>` (`src/components/Inert.tsx`).
- **Look.** `src/index.css` holds the real app's theme tokens and base rules verbatim. Icons come from `src/icons/registry.ts`, generated by `scripts/extract-icons.mjs` from the saved pages. Inter is served from `public/fonts/`. Brand, channel and customer images live in `public/images/`; reference them through `asset()` (`src/lib/asset.ts`) so the Pages base path is applied.
- **Store.** `src/store/store.ts` keeps one `DemoState`, seeded from `src/store/fixtures.ts` and persisted to one localStorage key. Read with `useDemo(selector)`, write with `updateDemo(current => next)`. `?reset=1` on any URL restores the fixtures.
- **Build and deploy.** `npm run build` type-checks, builds to `dist/` under the `/zaapi-take-home/` base path and copies `index.html` to `404.html` so Pages serves deep links. `.github/workflows/pages.yml` publishes `dist/` on every push to `main`; the squash merge is the release. Public URL: `docs/third-parties.md`.

## Non-negotiable invariants

Each has one suite in `docs/testing.md` and is never weakened to make a feature pass; renegotiate with the user.

1. **No outbound network.** The built demo requests nothing from any host but its own origin: no CDN fonts, no analytics, no API.
2. **Every route renders.** Every route in the table answers 200, renders with no console error or uncaught exception, carries its catalog title, and links only to routes in the table.
3. **No secret reaches git or output.** Gitleaks over the full history (pre-commit hook, `scripts/gate`, CI), plus a test that `.env` stays git-ignored and that `src/`, which ships to a public page, holds no credential-shaped literal.

## Alternatives considered: don't relitigate without new facts

| Rejected | Why | Date | Whose decision |
|---|---|---|---|
| Backend, database, cloud or VPS deployment of any kind | Out of scope for this take-home; front-end only, GitHub is the only destination | 2026-10-01 | User |
| Next.js static export | Heavier, no fidelity gain over Vite (ADR 0001) | 2026-10-01 | Session, on the user's stack-agnostic brief |
| Lucide or any other icon library | The user wants identical glyphs; icons are extracted from the saved pages | 2026-10-01 | User |
| Live capture of pages that were never screenshotted | Dropped | 2026-10-01 | User |
| Building pages without a screenshot (Analytics, Broadcast, Contacts, Notifications, Search, AI Deploy and Analyse, Settings other than Billing) | Pages without screenshots are not built; their entry points render but are inert | 2026-10-01 | User |
